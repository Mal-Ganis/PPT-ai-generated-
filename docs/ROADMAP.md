# 项目完善路线图

本文档汇总 **PPT 智能生成系统** 在功能、工程化、安全与运维方面可继续完善的工作项，供迭代规划与协作参考。

> **当前状态（概要）**  
> 核心业务链路已较完整：输入 → 大纲 → 正文 → 引用 → 预览 → 评估，并具备 JWT 登录与角色权限。  
> 主要差距在：**生产部署、安全加固、真实 PPT 导出、测试与用户管理**。

---

## 优先级说明

| 级别 | 含义 |
|------|------|
| **P0** | 上线前必做 |
| **P1** | 产品完整性 / 团队使用 |
| **P2** | 体验优化 / 长期运维 |

建议实施顺序：**P0 能安全上线 → P1 像完整产品 → P2 可长期运维**。

---

## 一、上线必做（P0）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **密钥安全** | `application.yml`、`env.example` 可能存在 API Key 默认值 | 全部改为占位符；密钥仅通过环境变量注入；已泄露 Key 立即轮换 | 防止被盗刷、满足合规 |
| **JWT / 默认密码** | JWT 存在 dev 默认 secret；种子账号弱密码 | 生产强制 `JWT_SECRET`；修改默认管理员密码；可选首登改密 | 防 token 伪造与弱口令 |
| **公开注册** | 任何人可注册（默认 VIEWER） | ✅ 已实现：默认只读 + 邀请码直开 EDITOR + 管理员审批提权 | 保留自助注册且可控 |
| **CORS** | 仅允许 `http://localhost:5173` | 生产域名白名单，或 Nginx 同域反代 | 上线后前端可正常调 API |
| **部署方案** | 仅有 Postgres 的 `docker-compose.yml` | 补充 Dockerfile、Nginx 配置、全栈 compose 与部署文档 | 可重复、可迁移上线 |
| **`.gitignore`** | 未忽略 `backend/target/`、`dist/` 等 | 加入构建产物忽略规则；仓库只保留源码 | 仓库干净、避免误提交 |
| **数据库策略** | 默认 `ddl-auto: update` | 生产使用 `validate` + Flyway/Liquibase 版本化迁移 | Schema 可控、可回滚 |
| **README** | 部分内容与现状不同步（如鉴权、CORS 位置） | 同步登录/JWT、部署步骤、环境变量说明 | 便于他人接手与部署 |

## 二、产品完整性（P1）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **PPT 文件导出** | 仅有 Markdown 导出；`pptContent` 为页面展示 | 生成 `.pptx` 并提供下载（Apache POI 或独立服务） | 用户真正「拿到 PPT 文件」 |
| **PDF 导出** | 无 | 打印样式或后端 PDF 生成 | 分享、存档 |
| **用户管理** | 无管理员后台 | ✅ 已实现：用户列表、改角色、审批、邀请码（首页「用户管理」） | 团队/multi-user 必备 |
| **密码找回** | 无 | 管理员重置或邮件找回流程 | 降低运维成本 |
| **引用与要点绑定** | 引用为页级 `sources[]` | 要点 ↔ 引用结构化绑定 | 引用更精准、可核对 |
| **项目协作** | 基本按 owner + 角色 | 项目分享、只读链接、多用户协作 | 团队场景 |
| **历史项目 owner** | 旧数据 owner 可能为空 | 数据迁移 + 统一归属规则 | 权限一致 |
| **大文件上传** | 无明确大小限制与前端提示 | 前后端限制 + 友好错误信息 | 避免大 PDF 上传失败无说明 |

## 三、体验与界面（P1–P2）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **登录页** | 已去除演示账号与开发口吻 | 可选：关闭注册 Tab、企业 Logo、备案信息 | 更像正式产品 |
| **移动端** | 有响应式，预览/编辑小屏仍拥挤 | 预览页移动布局、侧栏折叠优化 | 手机端可用 |
| **加载与进度** | 长任务有部分进度提示 | 生成正文/PPT 要点统一进度条、支持取消 | 减少等待焦虑 |
| **错误提示** | 部分仍使用 `alert()` | 统一 toast / 对话框组件 | 体验一致 |
| **无障碍** | 部分 `aria-label` | 键盘导航、焦点管理、skip link | 可访问性 |
| **国际化** | 全中文硬编码 | 如需对外可接入 i18n | 扩展用户群 |
| **首页/营销** | Hero 偏功能展示 | 使用流程、权限说明、案例截图 | 新用户上手更快 |

## 四、AI 与内容质量（P1–P2）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **按引用重生** | 已有接口，质量依赖 LLM | 持续优化 prompt 与后处理（去文献腔） | 讲稿更自然 |
| **引用格式** | 已支持 JSON → 可读行规范化 | 旧项目一键批量格式化引用 | 清理历史脏数据 |
| **知识检索** | 高亮 + 向量/字面双排序 | 带词跳转自动检索、无重合提示 | 补引用更高效 |
| **大纲/正文一致性** | 有章节锚点 | 章节覆盖率检查、漏页/重复提示 | 结构更稳 |
| **自评重跑** | 默认关闭（提速） | 可配置开启 + 阈值说明 UI | 质量与速度可选 |
| **模板/风格** | 偏单一商务风 | 多套 prompt 模板（学术/汇报/路演） | 场景适配 |
| **演讲时长** | 有时长规划逻辑 | 预览页展示预估演讲分钟数 | 更贴近真实汇报 |

## 五、工程与质量（P1–P2）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **单元测试** | 后端几乎无 test 目录 | Service 核心逻辑单测 | 防回归 |
| **集成测试** | 无 | 登录 + 创建项目 + 生成 API 集成测试 | 发布有信心 |
| **E2E** | 无 | Playwright 覆盖主流程 | 端到端验证 |
| **验收脚本** | `scripts/acceptance-test.ps1` 未带 JWT | 更新为带 token 的自动化验收 | 与鉴权对齐 |
| **CI/CD** | 无 GitHub Actions | push 时 build + test + lint | 协作规范 |
| **API 文档** | 无 Swagger | springdoc OpenAPI `/v3/api-docs` | 前后端对齐 |
| **限流** | 无 | LLM/检索接口按用户或 IP 限流 | 防成本失控 |
| **日志** | 基础 SLF4J | logback 配置、请求 correlation id | 便于排查 |
| **监控** | 仅 `/actuator/health` | Prometheus / uptime 告警 | 线上可观测 |
| **Actuator** | 对公网 permitAll | 生产鉴权或仅内网暴露 | 减少信息泄露 |

| 方向 | 现状 | 建议完善 | 价值 |

## 七、安全加固（P1）

| 方向 | 现状 | 建议完善 | 价值 |
|------|------|----------|------|
| **Token 存储** | localStorage | 评估 httpOnly Cookie 或 refresh token | 降低 XSS 风险 |
| **HTTPS** | 文档有提及 | Nginx + Certbot 作为标配 | 传输加密 |
| **上传安全** | 有文件类型校验 | 文件名消毒、大小限制（可选病毒扫描） | 防恶意文件 |
| **权限细粒度** | URL 级角色控制 | 统一项目级 ACL 策略文档 | 权限清晰 |
| **健康检查详情** | `show-details: always` | 生产改为 `when-authorized` | 少暴露内部信息 |

## 建议实施阶段

### 阶段 1：能安全上线（P0）

- 密钥 / JWT / 默认密码
- CORS 或 Nginx 同域
- `.gitignore` 与 README
- 关闭或限制公开注册
- 基础部署文档（Docker + Nginx）

### 阶段 2：像完整产品（P1）

- `.pptx` 导出
- 用户管理后台
- API 限流
- 测试 + CI
- 引用结构化（要点级）

### 阶段 3：可长期运维（P2）

- Flyway 迁移
- 数据库备份
- 监控与告警
- 审计日志
- 多模板 / 协作能力
